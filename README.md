# Волчица и Крылья 🐺🪽

Магазин авторских дескматов с фан-артом по гача-играм (Arknights, ZZZ, HSR, Genshin). Магазин не успел открыться — жизнь распорядилась иначе, а код остался и работает: витрина, заявки, админка, деплой-обвязка. Юридические страницы честно признают, что сайт демонстрационный.

**Живой стенд:** [wolfandwings.ru](https://wolfandwings.ru/)

> **Статус: WIP.** Требует больших тестов и дальнейшей разработки. Оплата не подключена (нужны ИП и эквайринг) — заказ оформляется заявкой, всё остальное работает целиком.

> **Про ИИ честно:** значительная часть кода, тестов, деплой-файлов и этого README написана ИИ-ассистентом. Архитектура, решения и шутки — человека.

## Что внутри

- Строгий CSP с per-request nonce, host-guard админка за SSH-туннелем, rate-limiting, защита от IDOR — и **тесты на каждое из этих обещаний** (модель угроз со ссылками на код — в [SECURITY.md](SECURITY.md))
- Каталог с серверной фильтрацией: URL — источник истины, RSC-рендер, Go-API с параметрическими запросами
- Единая форма заявки на карточке товара → Telegram-уведомление → server-side админка с CSRF и ротацией пароля
- Атомарные релизы через `current`-symlink с откатом, watchdog → Telegram, бекапы pg_dump с ротацией
- Изоляция сервисов: web и api — самостоятельные юниты без shell, узкие sudoers для деплоя, ufw/fail2ban

## Как устроено

```
web/      Next.js 16 (App Router, RSC) — витрина, БД не трогает
api/      Go 1.26 (chi, database/sql) — каталог, заявки, админка, единственный хозяин БД
deploy/   Caddy, systemd, setup.sh
```

Городские блоки, а не монолит: web умеет падать отдельно от api, api не знает про вёрстку, единственная точка слияния — HTTP на loopback.

- SQLite (дев, pure-Go без CGO) / Postgres (прод, pgx), миграции зашиты в бинарник, первый старт сам сидит демо-контент
- Цены в копейках (int), снапшот позиций заказа в схеме и сиде

## Запуск

```bash
cd api && go run ./cmd/api     # :8080, sqlite, всё намигрирует и насидит сам
cd web && pnpm i && pnpm dev   # :3000, /api проксируется на :8080
```

Секреты не нужны: без `TG_BOT_TOKEN` уведомления молча пропускаются.

Гостевой lookup можно проверить сразу: на `/order` сид создаёт демо-заказ **WW-2026-0001** / email **buyer@example.com**.

## Проверка

```bash
cd api && go vet ./... && go test ./... && go build ./...
cd web && pnpm lint && pnpm build
```

Тесты: сид и фильтры каталога, невидимость draft-товаров и неопубликованных художников, ротация пароля админа, IDOR-lookup заказа, валидация заявки, security-заголовки, rate-limit, host-guard, CSRF и полный цикл логина админки.

## Прод

**Установка сервера одной строкой** (Ubuntu 24.04 / Debian 12–13, от root):

```bash
curl -fsSL https://raw.githubusercontent.com/ViraMisal/wolfandwings/main/deploy/setup.sh | sudo bash -s -- --user vasya --key 'ssh-ed25519 AAAA...'
```

Скрипт-загрузчик клонирует репозиторий в `/opt/wolfandwings/src` и запускает полный провижинер `deploy/provision.sh`: Postgres, Caddy, сервис-юзеры, SSH по ключам, ufw, fail2ban, watchdog, бекапы pg_dump. Осторожный вариант — сначала скачать и прочитать, потом выполнить; `REPO`, `BRANCH` и `APP_DIR` переопределяются переменными окружения. Повторный запуск безопасен: ветка подтягивается, идемпотентность — по мере разумного.

Дальше — доставка артефактов: бинарник api и Next standalone кладутся в релизные папки, переключается `current`-symlink (атомарно), откат — вернуть symlink назад.
