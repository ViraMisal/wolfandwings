# Security — модель угроз

Формат: активы → границы доверия → угрозы → контрмеры, со ссылками на код. Плюс принятые риски — честно и с обоснованием.

## Активы

1. ПДн клиентов: имена, контакты (email / телефон / ник в Telegram) — 152-ФЗ, сервер и БД в РФ
2. Заявки/предзаказы — будущая выручка
3. Админка: управление каталогом и страницами
4. Инфраструктура: сервер, БД

## Границы доверия

```
интернет → Caddy → web (Next, 127.0.0.1:3000) → api (Go, 127.0.0.1:8080) → SQLite/Postgres
                          SSH-туннель → api /admin (host-guard panel.*)
```

Наружу торчит только витрина через Caddy. Админка публичной DNS-записи не имеет.

## Угрозы → контрмеры

| Угроза | Контрмера | Где |
|---|---|---|
| SQL-инъекции | только параметрические запросы; `ph()` подставляет `?`/`$N`, не данные | `api/internal/store/*` |
| XSS | React-экранирование + CSP с per-request nonce на `<script>`; стили — только внешние файлы (`style-src` без `unsafe-inline`) | `web/src/proxy.ts` |
| CSRF админки | токен в каждой POST-форме, у формы логина — double-submit cookie | `api/internal/admin/handlers.go` |
| IDOR заказов | lookup строго по паре номер + email | `api/internal/store/orders.go` |
| Утечка неопубликованного контента | draft-товары и черновики-художники невидимы для публичных lookup по slug, включая прямые ссылки (фильтр статусов + тесты) | `api/internal/store/content.go` |
| Перехват учётки админа | пароль ротируется из `ADMIN_PASSWORD` при старте; дев-дефолт только в dev, в prod пустой пароль запрещён | `api/internal/store/seed.go`, `api/internal/config/config.go` |
| Брутфорс форм | rate-limit: заявки, lookup, логин админки; IP — правый элемент X-Forwarded-For (его дописывает доверенный Caddy), клиентский левый не доверенный | `api/internal/httpx/middleware.go` |
| Утечка секретов | `.env` вне git (chmod 600, читает systemd), gitleaks в CI | `deploy/setup.sh`, `.github/workflows/ci.yml` |
| Supply chain | pinned lockfiles + govulncheck и pnpm audit в CI | `.github/workflows/ci.yml` |
| SAST-регресс | gosec в CI (G202 исключён: `ph()` — плейсхолдеры, не пользовательский ввод) | там же |
| Захват сервера | ufw (22/80/443, остальное DROP), fail2ban, SSH только ключи, root-логин off, авто security-патчи | `deploy/setup.sh` |
| Побег сервиса / lateral movement | systemd: системные юзеры без shell, seccomp + MDWE + read-only FS (api), egress-фильтр на loopback (web), изолированные деплой-пути | `deploy/systemd/*` |
| Компрометация админ-сессии | наружу не торчит (host-guard + 127.0.0.1), cookie HttpOnly+SameSite, TTL 12ч | `api/internal/admin/auth.go` |
| Карточные данные | не храним: оплата не подключена, эквайринг будет на стороне провайдера | — |

## Принятые риски (осознанно)

- **TG-уведомление — at-most-once.** Если API упадёт между записью заявки и отправкой, сообщение потеряется. Приемлемо: заявка уже в БД и видна в админке. При появлении оплаты (деньги = at-least-once) — mini-outbox или брокер.
- **Контакт клиента (email/телефон) уходит в Telegram открытым текстом.** Это необходимо, чтобы связаться по заявке; Telegram — обработчик ПДн в терминах 152-ФЗ, учтено в политике. Шифровать нечего: бот-чат приватный.
- **TOTP не нужен:** админка доступна только с сервера через SSH-туннель — фактор знания уже есть (SSH-ключ).
- **/metrics без аутентификации:** слушает только 127.0.0.1, Caddy не проксирует.
- **`sslmode=disable` к Postgres:** коннект по loopback внутри одного хоста — TLS избыточен.
